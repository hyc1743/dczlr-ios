# Native XA metadata reader

`native/resource/dc_xa.c` validates the admitted serialized XA profile and loads
numeric clip fields into `dc_animation_clip` and `dc_animation_timing`. It is
allocation-free. It accounts for material, event, morph and bone sections using
bounded lengths/counts, then requires the input to end exactly at the parsed
boundary. Encoded names and key payloads remain opaque; this is not a complete
pose/material/event decoder.

The observed disk clip table has 512 records of 108 bytes. Original in-memory
records use 112 bytes, including a runtime iteration byte and padding absent
from the file. The native API reads little-endian numeric values without
normalizing float bit patterns, flags or chain indices. It initializes runtime
iteration/reserved bytes to zero. This is a fresh-table API, not proof of
original in-place reload behavior with an existing iteration counter.

All framing is validated before an output array is modified. Truncation,
unknown section flags, impossible counts, trailing bytes, insufficient capacity
and overlapping buffers fail without changing outputs. The admitted section
flags are 0/1; unsafe/unknown original input behavior is not reproduced. Runtime
animation APIs separately reject unsupported values when selected for use.
Files without a clip table are valid metadata inputs and return `DC_NOT_FOUND`
when asked for clips; no default table is synthesized.

## Evidence and coverage

Section framing comes from the existing read-only Ghidra exports of
`0x0040bd50`, `0x0040dc80`, `0x0040df50`, `0x0040e310` and `0x0040e8e0` for
the pinned local PE. These are standalone analysis exports, not REA Evidence.

`tools/oracle_xa_clips.py` independently executes the original 711-byte clip
loader and 72-byte name decoder on 512 self-authored records. memcpy is a
bounded synthetic copy boundary. Instruction addresses, names-only writes,
cursor updates, copies and returns are guarded, with a finite instruction
budget. All exposed numeric descriptor bytes match, including special float
bit patterns. Names are outside the native API/comparison. Original iteration
bytes start at zero in this harness. The complete XA loader, heap allocations,
model linking and key interpretation are not executed by this oracle. The
public fixture contains only hashes and coverage metadata.

The current local audit recognizes 81 XA entries. Their native section counts
and table offsets match the separately implemented Python framing probe for
the same source hashes. Numeric fields match serialized bytes directly. There
are 74 clip tables (37,888 records); seven entries have no clip table. These
results exclude the still-unrecognized `rpsp_02.pp` archive and do not establish
pose sampling, audio/event behavior, rendering or game playability. Reports
contain metadata/hashes only and remain local.

```sh
python tools/oracle_xa_clips.py --exe research/target.exe \
  --output research/native-core/xa-clips-oracle.json \
  --vectors tests/fixtures/xa-clips-original-vectors.json
python tools/audit_native_xa.py --data Data \
  --reference research/native-core/xa-framing-audit.json \
  --output research/native-core/native-xa-audit.json
python -m unittest discover -s tests -p test_native_xa.py -v
```

The reference report is generated by the separately retained local framing
probe. Without `--reference`, the audit still checks native numeric output
against serialized bytes, but does not claim an independent framing comparison.

## Host integration

The iOS checker now constructs its own minimal XA fixture, loads its table with
the native reader and passes a decoded repeating clip to the native animation
tick. A successful pipeline is reported only after a positive-delta sample
change and presentation. The simulator gate requires checker presentation,
animation advancement and `PORTLAB_NATIVE_XA_FIXTURE_LOADED`; a first frame or
an echoed marker cannot satisfy it. No original resource is supplied to cloud
builds.

Source `f9d275a832f7dcd6818d2f4ca16fe98e9653e34d` passed 86 portable tests,
device IPA packaging and the iPhone 16 Pro/iOS 18.5 simulator pipeline in run
`39976603576`. Its app log contains the checker-present, XA-fixture-loaded and
animation-advanced markers, and its screenshot was inspected. Run `39976638796`
passed 55 ARM64 macOS native tests, explicit iPhoneOS SDK compilation (including
`dc_xa.o`) and Apple archive/image adapter checks. Downloaded artifacts matched
the pinned source hashes; the device IPA was inspected as unsigned ARM64/iPhoneOS
with the matching manifest and no PP/XX/XA/resource-part/EXE bundle members.
This verifies the self-authored diagnostic pipeline, not original game flow.

Original resource binding, material/pose sampling, the startup transition
composition and subsequent game flow remain incomplete.
